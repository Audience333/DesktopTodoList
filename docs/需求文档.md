## 1. 项目背景与目标

### 1.1 背景

日常工作中，待办事项往往散落在便签、聊天记录、邮件和记忆中，存在以下问题：

- **记录成本高**：打开厚重的项目管理工具只需要记一句话，性价比低。
- **容易遗忘**：缺少桌面级提醒，任务记录后不再被看见。
- **隐私顾虑**：在线待办服务需要账号登录、数据上传云端。
- **启动慢 / 依赖重**：Electron 类应用安装包动辄上百 MB，冷启动数秒。

### 1.2 项目目标

开发一款 **Windows 原生兼容、免安装、离线优先** 的轻量桌面待办工具，满足：

| 编号 | 目标 | 可度量指标 |
| --- | --- | --- |
| G1 | 快速记录 | 从唤起窗口到任务落库 ≤ 3 秒，键盘可全流程操作 |
| G2 | 不遗忘 | 支持到期提醒，提醒触发误差 ≤ 30 秒 |
| G3 | 数据私有 | 全部数据仅存本机，无网络请求，无账号体系 |
| G4 | 轻量 | 安装包/分发体积 < 5 MB，冷启动 < 1 秒，常驻内存 < 120 MB |
| G5 | 好用 | 主流程（新增/完成/删除/筛选）零学习成本 |

### 1.3 非目标（Out of Scope）

以下内容 **v1.0 明确不做**，避免范围蔓延：

- 多端同步、账号登录、云备份
- 团队协作、任务指派、评论
- 甘特图、看板、子任务无限层级
- 移动端（Android / iOS）与 macOS / Linux 版本
- 番茄钟、时间统计报表等效率扩展功能

## 3. 技术方案（建议）

### 3.1 技术选型对比

| 方案 | 体积 | 启动 | 原生集成 | 结论 |
| --- | --- | --- | --- | --- |
| **纯 HTML/CSS/JS + 本地存储 + 轻量宿主** | < 1 MB | < 0.5 s | 中（需宿主提供托盘/通知） | ✅ **推荐 v1.0** |
| Electron | ~150 MB | 2–4 s | 强 | ❌ 与 G4 轻量目标冲突 |
| Tauri (Rust) | ~5 MB | < 1 s | 强 | ⭕ 体积合格但引入 Rust 工具链，环境要求高 |
| .NET WPF / WinUI 3 | ~10 MB | < 1 s | 最强 | ⭕ 需 .NET SDK，跨技术栈维护成本高 |
| Python + PySide6 | ~40 MB | 2–3 s | 中 | ❌ 打包与杀软误报风险 |

### 3.2 推荐架构（v1.1）

```
┌──────────────────────────────────────────────┐
│  表现层  index.html + styles.css + app.js    │
│  · 任务列表 / 筛选 / 编辑 / 拖拽排序          │
│  · 浮窗紧凑布局 / 设置面板                     │
│  · 纯前端，无框架依赖（零构建步骤）           │
├──────────────────────────────────────────────┤
│  应用层  store.js（状态与业务规则）           │
│  · 增删改查、排序、筛选、统计                 │
├──────────────────────────────────────────────┤
│  持久层  storage.js                          │
│  · localStorage 主存储 + JSON 导入导出        │
│  · 自动备份与损坏数据恢复                     │
│  · hostCommand 通道：向宿主下发窗口指令       │
├──────────────────────────────────────────────┤
│  宿主层  host\launcher.ps1 + Edge --app      │
│  · 无边框浮窗 / 置顶置底 / 可选中切换          │
│  · 开机自启 / 全局快捷键 / 托盘 / 系统通知     │
└──────────────────────────────────────────────┘
```

**设计原则**

1. **零依赖**：不引入任何 npm / CDN 依赖；宿主层仅使用 Windows 自带组件（PowerShell 5.1 + Edge），无需安装任何运行时。
2. **分层降级**：核心任务功能在纯浏览器环境（直接打开 `index.html`）完全可用；浮窗、置顶置底、穿透、自启、托盘等仅宿主模式可用，缺失时对应设置项置灰并说明原因，而非静默失效。
3. **单一数据源**：所有状态集中在 `store`，UI 只做渲染，禁止直接操作 localStorage。
4. **失败可见**：任何宿主指令（写注册表、改窗口样式）失败都必须反馈到界面，不允许静默失败。

### 3.3 数据模型

```jsonc
{
  "schemaVersion": 1,
  "tasks": [
    {
      "id": "t_1739500000000_a1b2",   // string, 唯一
      "title": "提交周报",             // string, 1–200 字符, 必填
      "note": "包含本周进度与风险",     // string, 0–2000 字符, 可选
      "priority": "high",             // "high" | "medium" | "low"
      "status": "todo",               // "todo" | "done"
      "dueAt": "2026-02-14T17:00:00", // ISO 本地时间字符串, 可为 null
      "remind": true,                 // boolean, 是否提醒
      "tags": ["工作"],               // string[], 最多 5 个
      "order": 1.5,                   // number, 排序权重（浮点，便于插入）
      "createdAt": "2026-02-14T09:00:00",
      "updatedAt": "2026-02-14T09:30:00",
      "completedAt": null             // ISO 字符串, status=done 时必填
    }
  ],
  "settings": {
    "theme": "system",                // "system" | "light" | "dark"
    "defaultFilter": "today",         // 启动默认视图
    "hotkey": "Ctrl+Alt+T",
    "remindAdvanceMinutes": 0,
    "weekStartsOn": 1,                // 0=周日, 1=周一

    // —— 窗口行为（v1.1 新增）——
    "autoStart": false,               // 开机自启
    "startMinimized": false,          // 自启时最小化到托盘，不弹窗
    "windowMode": "normal",           // "normal" | "floating"
    "windowLayer": "normal",          // "top" | "normal" | "bottom"
    "selectable": true,               // false = 鼠标穿透（不可选中）
    "floatingGeometry": {             // 浮窗模式下的位置与尺寸
      "x": null, "y": null,           // null = 首次运行时取右下角默认位
      "w": 360, "h": 480
    },

    // —— 列表级选择（v1.2 新增）——
    "multiSelectEnabled": true,       // 是否启用多选（关闭则退化为单选）
    "rubberBandSelect": true,         // 是否启用框选
    "keepSelectionAcrossViews": true  // 切换视图时是否保留不可见选中项
  }
}
```

**运行时状态（不持久化为业务数据）**：`selectedIds`（`Set<string>`）仅存于内存，程序重启后不恢复选择，避免用户下次打开时面对一批"莫名其妙已选中"的任务。

**存储键**：`desktopTodoList.v1`（localStorage）；备份键 `desktopTodoList.v1.backup`；宿主指令队列键 `desktopTodoList.hostQ`。

#### 4.6.1 「可选中 / 不可选中」语义定义

> **决策记录（v1.2）**：经确认，该需求包含**两个层面**，两者都要实现，编号与职责分离如下：
> - **窗口级** → FR-74：窗口能否被鼠标交互（鼠标穿透），见下文本节。
> - **列表级** → FR-80 及以后：任务条目能否被选中（多选、批量操作），见 §4.8。

**窗口级语义**

| 状态 | 名称 | 行为 | 典型用途 |
| --- | --- | --- | --- |
| 可选中 | Selectable（默认） | 窗口正常响应鼠标与键盘，可点击、可输入、可获得焦点 | 录入与整理任务时 |
| 不可选中 | Click-through / 鼠标穿透 | 鼠标事件穿透到下方窗口，点击浮窗不会夺走前台应用焦点；浮窗仅作只读展示 | 专注工作时把清单"钉"在屏幕角落当参考，不打断当前应用 |

**实现要点**

- 穿透由两个 Win32 扩展样式组合实现：
  - `WS_EX_TRANSPARENT`（`0x00000020`）：鼠标事件穿透到下层窗口
  - `WS_EX_LAYERED`（`0x00080000`）：分层窗口，穿透生效的必要条件
- 可选叠加 `WS_EX_NOACTIVATE`（`0x08000000`）：点击浮窗不抢焦点
- 通过 `SetWindowLong(hwnd, GWL_EXSTYLE, ...)` 后必须调用 `SetWindowPos(hwnd, 0,0,0,0,0, SWP_NOMOVE|SWP_NOSIZE|SWP_NOZORDER|SWP_FRAMECHANGED)` 使样式生效

> ⚠️ **FR-77 逃生机制（必须实现，否则视为缺陷）**
> 进入"不可选中"后，用户 **无法再点击浮窗来关闭该状态**。因此必须提供以下三条独立逃生通道，至少两条同时可用：
> 1. **全局快捷键** `Ctrl+Alt+L` 切换可选中/不可选中（`RegisterHotKey`，不受穿透影响）
> 2. **托盘菜单** 中的"允许交互"勾选项
> 3. **超时自动恢复**：穿透状态连续保持超过设定时长（默认关闭，可选 30 分钟）后自动恢复为可选中
>
> 首次开启穿透时，必须以浮窗内提示条明确告知用户如何使用快捷键恢复。

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-77 | 穿透状态逃生机制 | P0 | 进入穿透后，`Ctrl+Alt+L` 与托盘菜单均能恢复交互；拔掉此机制不得发布 |
| FR-78 | 穿透状态可见性 | P1 | 穿透时托盘图标显示不同角标/提示文字，让用户知道当前处于穿透态 |
| FR-79 | 层级唯一性 | P0 | 置顶与置底互斥，同时只能生效一个；切换时状态栏实时反映当前层级 |

### 4.8 列表级选择（多选）— v1.2 新增

用户确认「可选中 / 不可选中」同时包含列表层面的选中语义，本节定义任务条目的选择行为。

#### 4.8.1 选择模型

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-80 | 单选（默认） | P0 | 点击任务非交互区域，该任务被选中并高亮；同时清除其他选中项 |
| FR-81 | 取消选择 | P0 | `Esc` 或点击列表空白处清空选择；再点已选中项也可取消 |

| FR-83 | 连续选择 | P0 | `Shift+点击` 选中「锚点 → 当前项」之间的全部任务；锚点由上一次普通点击或 Ctrl+点击确定 |
| FR-84 | 全选 / 全不选 | P0 | `Ctrl+A` 全选当前视图可见任务；再按一次清空；表头提供全选复选框（含半选态） |
| FR-85 | 框选（橡皮筋） | P1 | 在列表空白区域按住并拖拽，划出选框，覆盖到的任务被选中；按住 `Ctrl` 框选为追加模式 |

| FR-89 | 批量取消完成 | P0 | 批量将选中任务恢复为待办 |
| FR-90 | 批量删除 | P0 | 批量删除选中任务；删除后 5 秒内可整体撤销恢复 |

#### 4.8.2 交互细则

| 场景 | 行为 |
| --- | --- |
| 点击任务标题 | 进入行内编辑，**不**改变选中状态（避免误触丢失多选） |
| 双击任务行 | 打开详情面板 |
| 悬停任务行 | 显示删除按钮与拖拽手柄，不显示复选框之外的选择控件 |
| 拖拽排序 vs 框选 | 在拖拽手柄上按下 = 排序；在任务行空白处按下 = 框选；在任务行内容上按下 = 选择 |
| 复选框列 | 行首为"完成"复选框（FR-04）；选中高亮为整行背景色变化，二者视觉上必须可区分 |
| 穿透模式（FR-74）生效时 | 列表多选自然不可用（窗口不接收鼠标）；恢复可选中后选择状态保持原样 |

## 9. 风险与对策

| 编号 | 风险 | 影响 | 对策 |
| --- | --- | --- | --- |
| R1 | 宿主层（PowerShell）无法访问系统托盘或注册表，或被杀软拦截脚本执行 | 高（四项窗口需求全部依赖宿主） | 优先只用 `HKCU` 与 `user32.dll` 等无需提权的接口；启动自检并在界面明确报告哪项能力不可用；仍保留纯浏览器降级入口 `src/index.html` |
| R2 | localStorage 被清理导致数据丢失 | 高 | 每日自动备份 + 一键导出 + 启动时检测并引导恢复 |
| R3 | 浏览器后台标签页定时器被节流，提醒延迟 | 中 | 宿主模式下保持活跃；提醒判定使用绝对时间对比而非累加计时 |
| R4 | 高 DPI 下无边框窗口模糊 | 中 | 显式声明 DPI 感知；使用 CSS 逻辑像素与 `devicePixelRatio` 校准 |
| R5 | 范围蔓延（不断加功能） | 中 | 严格遵守第 1.3 节非目标清单，新需求进入 v2.0 待办池 |
| R6 | **穿透模式导致用户"锁死"**，无法操作也无法关闭窗口 | 高 | FR-77 强制实现三条逃生通道（全局快捷键、托盘菜单、可选超时恢复）；开启时浮窗内明确提示 |
| R7 | 开机自启被安全软件拦截或注册表写入被拒 | 中 | 写入失败时给出明确错误而非静默失败；提供"生成启动快捷方式到启动文件夹"的备选方案（`shell:startup`） |
| R8 | 置底（`HWND_BOTTOM`）在部分场景下窗口被永久埋没、难以找回 | 中 | 置底状态下托盘菜单始终可恢复；全局快捷键可唤起；窗口失焦后若不可见则提示用户 |
| R9 | 宿主依赖 Edge 浏览器，用户环境缺失 Edge | 低 | 启动时检测 Edge 路径，缺失则回退到系统默认浏览器打开，并提示部分桌面功能不可用 |

## 11. 技术方案补充：宿主层选型（v1.1）

### 11.1 为何必须引入宿主

| 能力 | 纯浏览器 / HTML | 需要宿主 |
| --- | --- | --- |
| 任务增删改查、筛选、存储 | ✅ | |
| 页面内提醒 | ✅ | |
| 开机自启（注册表 Run 项） | ❌ | ✅ |
| 无边框浮窗 | ❌ | ✅ |
| 置顶 / 置底（`HWND_TOPMOST` / `HWND_BOTTOM`） | ❌ | ✅ |
| 鼠标穿透（`WS_EX_TRANSPARENT`） | ❌ | ✅ |
| 全局快捷键、系统托盘 | ❌ | ✅ |
| Windows 原生通知 | 部分（需 HTTPS/localhost 且用户授权） | ✅ |

### 11.2 宿主实现选型

| 方案 | 体积 | 需额外运行时 | 浮窗/置顶/穿透 | 结论 |
| --- | --- | --- | --- | --- |
| **PowerShell 5.1 + Edge `--app`** | ~50 KB 脚本 | 否（系统自带） | ✅ 全部可做 | ✅ **选定** |
| PowerShell + WinForms WebBrowser | ~50 KB | 否 | ✅ | ❌ 内核为 IE，不支持现代 CSS/JS |
| PowerShell + WebView2 SDK | ~1 MB | 需 .NET 绑定 | ✅ | ⭕ 本机 WebView2 运行时缺失（仅剩 `SetupMetrics` 目录），不满足零依赖 |
| Tauri (Rust) | ~5 MB | 需 Rust 工具链 + 构建 | ✅ | ❌ 环境要求超出"小工具"定位 |
| Electron | ~150 MB | 否 | ✅ | ❌ 违背轻量目标 G4 |
| HTA (`mshta.exe`) | ~0 | 否 | 部分 | ❌ 无托盘、无 `WS_EX_TRANSPARENT` 支持，且易被杀软拦截 |

**选定理由**：经环境探测确认本机具备 **PowerShell 5.1.26100** 与 **Edge（`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`）**，两者均为 Windows 10/11 系统自带组件，无需安装任何依赖即可获得完整的 Chromium 渲染能力与 Win32 窗口控制能力。

### 11.3 宿主工作机制

```
启动待办.bat
   └─> powershell -NoProfile -ExecutionPolicy Bypass -File host\launcher.ps1
         ├─ 单实例保护（命名 Mutex）+ 命名事件（-Stop / -Toggle 信号）
         ├─ 读取 %LOCALAPPDATA%\DesktopTodoList\host-settings.json 中的窗口偏好
         ├─ 启动 TcpListener 静态服务器（127.0.0.1 随机高位端口 + 随机 token）
         ├─ 创建消息专用窗口（收 WM_HOTKEY / 托盘回调）
         ├─ 添加托盘图标与右键菜单
         ├─ 启动: msedge.exe --app="http://127.0.0.1:<port>/index.html?host=1&p=<port>&t=<token>"
         │        --user-data-dir=<独立配置目录>
         ├─ 按窗口标题轮询定位 HWND（Edge --app 窗口标题取自页面 <title>）
         ├─ P/Invoke user32.dll 应用窗口状态：
         │     Set-WindowLayer      → SetWindowPos(HWND_TOPMOST | HWND_BOTTOM | HWND_NOTOPMOST)
         │     Set-WindowSelectable → SetWindowLong(GWL_EXSTYLE) + SetWindowPos(SWP_FRAMECHANGED)
         ├─ RegisterHotKey（Ctrl+Alt+T 显隐、Ctrl+Alt+L 切换穿透）
         └─ 主循环：PeekMessage + 非阻塞 HTTP 泵 + 指令消费 + 命名事件 + Edge 存活检测
```

**宿主 ↔ 页面通信**

| 方向 | 方式 | 用途 |
| --- | --- | --- |
| 页面 → 宿主 | `POST /__host/cmd?t=<token>`（批量 JSON 指令） | 移动/缩放窗口、切换层级与穿透、开机自启、同步待办数量 |
| 宿主 → 页面 | `GET /__host/resp?t=<token>`（轮询回执） | 宿主能力清单、窗口边界、最近错误、宿主侧实际状态 |

**为什么不用 localStorage 传指令**：页面运行在 `http://127.0.0.1:<port>` 源上，宿主若要读它的 localStorage 就得解析 Chromium 的 LevelDB（含 Snappy 压缩），代价高且随版本变化而失效。HTTP 通道双向、可校验、可观测，且复用已有的静态服务器，不额外占端口。

**为什么不用 `HttpListener`**：`HttpListener` 依赖 Windows 内核 `http.sys`，在容器、受限账户、部分精简系统上构造时即抛 `Operation is not supported on this platform`（本机实测复现）。因此改用 `TcpListener` + 手写的极简 HTTP 处理（仅需 `GET 静态文件` 与 `POST 小段 JSON`），只依赖基础 socket，任何环境可用。

**为什么必须非阻塞**：`AcceptTcpClient()` 与 `GetContext()` 都会无限期阻塞；一旦在消息循环里直接调用，托盘菜单与全局热键将全部失去响应。故采用 `BeginAcceptTcpClient` + `AsyncWaitHandle.WaitOne(0)` 的非阻塞泵。

### 11.4 浮窗模式下已知取舍

| 取舍 | 说明 |
| --- | --- |
| 圆角与阴影 | Edge 无边框窗口本身不带圆角；圆角需由页面 CSS 绘制，窗口四角仍为直角（可能露出桌面背景） |
| 拖拽移动 | 无边框窗口无法通过标题栏拖动，需页面内实现拖拽区域并回报坐标给宿主 |
| 任务栏图标 | `--app` 模式会占用一个任务栏按钮，无法完全隐藏 |
| 窗口标题 | 宿主依赖固定窗口标题定位 HWND，因此页面 `<title>` 不可随意更改 |
