## 1. 项目背景与目标

### 1.1 背景

日常工作中，待办事项往往散落在便签、聊天记录、邮件和记忆中，存在以下问题：

- **记录成本高**：打开厚重的项目管理工具只需要记一句话，性价比低。
- **容易遗忘**：缺少桌面级提醒，任务记录后不再被看见。
- **隐私顾虑**：在线待办服务需要账号登录、数据上传云端。
- **启动慢 / 依赖重**：Electron 类应用安装包动辄上百 MB，冷启动数秒。

### 1.2 项目目标

开发一款 **Windows 原生兼容、免安装、离线优先** 的轻量桌面待办工具，满足：

| 编号 | 目标 | 可度量指标 |
| --- | --- | --- |
| G1 | 快速记录 | 从唤起窗口到任务落库 ≤ 3 秒，键盘可全流程操作 |
| G2 | 不遗忘 | 支持到期提醒，提醒触发误差 ≤ 30 秒 |
| G3 | 数据私有 | 全部数据仅存本机，无网络请求，无账号体系 |
| G4 | 轻量 | 安装包/分发体积 < 5 MB，冷启动 < 1 秒，常驻内存 < 120 MB |
| G5 | 好用 | 主流程（新增/完成/删除/筛选）零学习成本 |

### 1.3 非目标（Out of Scope）

以下内容 **v1.0 明确不做**，避免范围蔓延：

- 多端同步、账号登录、云备份
- 团队协作、任务指派、评论
- 甘特图、看板、子任务无限层级
- 移动端（Android / iOS）与 macOS / Linux 版本
- 番茄钟、时间统计报表等效率扩展功能

## 3. 技术方案（建议）

### 3.1 技术选型

| 方案 | 运行时与集成 | 结论 |
| --- | --- | --- |
| **Win32 原生桌面应用（C++20）** | 直接调用 Windows 窗口、托盘、快捷键、通知和 UI Automation 接口；x64/ARM64 原生构建 | ✅ **当前交付方案** |
| HTML/JavaScript + 浏览器/脚本宿主 | 依赖浏览器、脚本启动器与本地服务，无法作为独立原生小插件交付 | ❌ 已由原生应用替代，不属于当前运行时 |
| Electron、WebView、Tauri 或额外托管运行时 | 增加运行时体积、维护面或目标机器依赖 | ❌ 不采用 |

### 3.2 原生分层架构

```text
┌─────────────────────────────────────────────────┐
│ Win32 窗口与渲染：浮窗、任务列表、编辑与设置     │
├─────────────────────────────────────────────────┤
│ Presentation：视图模型、布局、选择、输入与无障碍 │
├─────────────────────────────────────────────────┤
│ Application：应用服务、提醒编排、导入导出与设置   │
├─────────────────────────────────────────────────┤
│ Domain：任务、校验、查询、提醒、撤销与选择规则     │
├─────────────────────────────────────────────────┤
│ Persistence：版本化 JSON、原子保存、轮换备份       │
├─────────────────────────────────────────────────┤
│ Windows Platform：窗口、托盘、热键、通知、自启动   │
└─────────────────────────────────────────────────┘
```

构建使用 CMake 与 C++20；发布包含 x64 和 ARM64 的独立可执行文件、安装程序及便携包。程序离线运行，不嵌入浏览器/WebView、不启动本地 HTTP 服务或脚本宿主。

**设计原则**

1. **原生且轻量**：使用 Win32 与 Windows SDK；目标机不需要安装浏览器运行时、.NET、Node.js、PowerShell 或其他应用运行时。
2. **职责分层**：领域规则不依赖窗口实现；应用服务编排持久化和平台能力；表现层通过明确接口调用，不直接改写数据文件。
3. **单一持久数据源**：任务和设置保存在 `%LOCALAPPDATA%\DesktopTodoList\data.json`，以原子文件操作保存，并由每日备份与导入/导出保护。
4. **失败可见且安全**：文件、通知、热键和注册表操作失败时提供可理解的错误；卸载默认保留用户数据。

### 3.3 数据模型

```jsonc
{
  "schemaVersion": 1,
  "tasks": [
    {
      "id": "t_1739500000000_a1b2",   // string, 唯一
      "title": "提交周报",             // string, 1–200 字符, 必填
      "note": "包含本周进度与风险",     // string, 0–2000 字符, 可选
      "priority": "high",             // "high" | "medium" | "low"
      "status": "todo",               // "todo" | "done"
      "dueAt": "2026-02-14T17:00:00", // ISO 本地时间字符串, 可为 null
      "remind": true,                 // boolean, 是否提醒
      "tags": ["工作"],               // string[], 最多 5 个
      "order": 1.5,                   // number, 排序权重（浮点，便于插入）
      "createdAt": "2026-02-14T09:00:00",
      "updatedAt": "2026-02-14T09:30:00",
      "completedAt": null             // ISO 字符串, status=done 时必填
    }
  ],
  "settings": {
    "theme": "system",                // "system" | "light" | "dark"
    "defaultFilter": "today",         // 启动默认视图
    "hotkey": "Ctrl+Alt+T",
    "remindAdvanceMinutes": 0,
    "weekStartsOn": 1,                // 0=周日, 1=周一

    // —— 窗口行为（v1.1 新增）——
    "autoStart": false,               // 开机自启
    "startMinimized": false,          // 自启时最小化到托盘，不弹窗
    "windowMode": "normal",           // "normal" | "floating"
    "windowLayer": "normal",          // "top" | "normal" | "bottom"
    "selectable": true,               // false = 鼠标穿透（不可选中）
    "floatingGeometry": {             // 浮窗模式下的位置与尺寸
      "x": null, "y": null,           // null = 首次运行时取右下角默认位
      "w": 360, "h": 480
    },

    // —— 列表级选择（v1.2 新增）——
    "multiSelectEnabled": true,       // 是否启用多选（关闭则退化为单选）
    "rubberBandSelect": true,         // 是否启用框选
    "keepSelectionAcrossViews": true  // 切换视图时是否保留不可见选中项
  }
}
```

**运行时状态（不持久化为业务数据）**：`selectedIds`（`Set<string>`）仅存于内存，程序重启后不恢复选择，避免用户下次打开时面对一批"莫名其妙已选中"的任务。

**持久化位置**：`%LOCALAPPDATA%\DesktopTodoList\data.json`；每日备份位于同目录的 `backups\`。旧网页版本的 localStorage 仅作为用户手动导出 JSON 的来源，不再是本程序的存储后端。

#### 4.6.1 「可选中 / 不可选中」语义定义

> **决策记录（v1.2）**：经确认，该需求包含**两个层面**，两者都要实现，编号与职责分离如下：
> - **窗口级** → FR-74：窗口能否被鼠标交互（鼠标穿透），见下文本节。
> - **列表级** → FR-80 及以后：任务条目能否被选中（多选、批量操作），见 §4.8。

**窗口级语义**

| 状态 | 名称 | 行为 | 典型用途 |
| --- | --- | --- | --- |
| 可选中 | Selectable（默认） | 窗口正常响应鼠标与键盘，可点击、可输入、可获得焦点 | 录入与整理任务时 |
| 不可选中 | Click-through / 鼠标穿透 | 鼠标事件穿透到下方窗口，点击浮窗不会夺走前台应用焦点；浮窗仅作只读展示 | 专注工作时把清单"钉"在屏幕角落当参考，不打断当前应用 |

**实现要点**

- 穿透由两个 Win32 扩展样式组合实现：
  - `WS_EX_TRANSPARENT`（`0x00000020`）：鼠标事件穿透到下层窗口
  - `WS_EX_LAYERED`（`0x00080000`）：分层窗口，穿透生效的必要条件
- 可选叠加 `WS_EX_NOACTIVATE`（`0x08000000`）：点击浮窗不抢焦点
- 通过 `SetWindowLong(hwnd, GWL_EXSTYLE, ...)` 后必须调用 `SetWindowPos(hwnd, 0,0,0,0,0, SWP_NOMOVE|SWP_NOSIZE|SWP_NOZORDER|SWP_FRAMECHANGED)` 使样式生效

> ⚠️ **FR-77 逃生机制（必须实现，否则视为缺陷）**
> 进入"不可选中"后，用户 **无法再点击浮窗来关闭该状态**。因此必须提供以下三条独立逃生通道，至少两条同时可用：
> 1. **全局快捷键** `Ctrl+Alt+L` 切换可选中/不可选中（`RegisterHotKey`，不受穿透影响）
> 2. **托盘菜单** 中的"允许交互"勾选项
> 3. **超时自动恢复**：穿透状态连续保持超过设定时长（默认关闭，可选 30 分钟）后自动恢复为可选中
>
> 首次开启穿透时，必须以浮窗内提示条明确告知用户如何使用快捷键恢复。

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-77 | 穿透状态逃生机制 | P0 | 进入穿透后，`Ctrl+Alt+L` 与托盘菜单均能恢复交互；拔掉此机制不得发布 |
| FR-78 | 穿透状态可见性 | P1 | 穿透时托盘图标显示不同角标/提示文字，让用户知道当前处于穿透态 |
| FR-79 | 层级唯一性 | P0 | 置顶与置底互斥，同时只能生效一个；切换时状态栏实时反映当前层级 |

### 4.8 列表级选择（多选）— v1.2 新增

用户确认「可选中 / 不可选中」同时包含列表层面的选中语义，本节定义任务条目的选择行为。

#### 4.8.1 选择模型

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-80 | 单选（默认） | P0 | 点击任务非交互区域，该任务被选中并高亮；同时清除其他选中项 |
| FR-81 | 取消选择 | P0 | `Esc` 或点击列表空白处清空选择；再点已选中项也可取消 |
| FR-82 | 追加选择（不连续） | P0 | `Ctrl+点击` 切换单项选中状态，不影响其他已选项 |
| FR-83 | 连续选择 | P0 | `Shift+点击` 选中「锚点 → 当前项」之间的全部任务；锚点由上一次普通点击或 Ctrl+点击确定 |
| FR-84 | 全选 / 全不选 | P0 | `Ctrl+A` 全选当前视图可见任务；再按一次清空；表头提供全选复选框（含半选态） |
| FR-85 | 框选（橡皮筋） | P1 | 在列表空白区域按住并拖拽，划出选框，覆盖到的任务被选中；按住 `Ctrl` 框选为追加模式 |
| FR-86 | 键盘选择 | P1 | `↑/↓` 移动焦点并可配合 `Shift` 扩展选择；`Space` 切换当前项选中；移动时不触发滚动抖动 |
| FR-87 | 选中计数 | P0 | 一旦有选中项，底部出现批量工具栏，显示"已选 N 项" |
| FR-88 | 批量完成 | P0 | 批量标记选中任务为已完成 |
| FR-89 | 批量取消完成 | P0 | 批量将选中任务恢复为待办 |
| FR-90 | 批量删除 | P0 | 批量删除选中任务；删除后 5 秒内可整体撤销恢复 |
| FR-91 | 批量设置优先级 | P1 | 批量为选中任务设置高/中/低优先级 |
| FR-92 | 批量设置截止时间 | P2 | 批量为选中任务设置同一截止时间 |
| FR-93 | 批量加标签 | P2 | 批量为选中任务添加/移除标签 |
| FR-94 | 与"完成"复选框互不干扰 | P0 | 点击复选框只切换完成状态，**不改变选中状态**；点击复选框不得被当作选择操作 |
| FR-95 | 视图切换时的选择处理 | P0 | 切换视图或筛选后，已选中但不在当前视图中的任务：默认**保留选择但不显示**，批量工具栏提示"其中 M 项不在当前视图"；提供"仅选择当前视图"快捷操作 |
| FR-96 | 数据变更后的选择清理 | P0 | 任务被删除（含其他方式删除）后，其选中状态自动移除，不残留失效 id |

#### 4.8.2 交互细则

| 场景 | 行为 |
| --- | --- |
| 点击任务标题 | 进入行内编辑，**不**改变选中状态（避免误触丢失多选） |
| 双击任务行 | 打开详情面板 |
| 悬停任务行 | 显示删除按钮与拖拽手柄，不显示复选框之外的选择控件 |
| 拖拽排序 vs 框选 | 在拖拽手柄上按下 = 排序；在任务行空白处按下 = 框选；在任务行内容上按下 = 选择 |
| 复选框列 | 行首为"完成"复选框（FR-04）；选中高亮为整行背景色变化，二者视觉上必须可区分 |
| 穿透模式（FR-74）生效时 | 列表多选自然不可用（窗口不接收鼠标）；恢复可选中后选择状态保持原样 |

## 10. 已确认的产品决策

本节记录已确认的范围，不再作为待开发前的开放问题：

1. **交付形态**：Windows 原生桌面悬浮插件；不交付 HTML 页面或浏览器壳。
2. **系统范围**：提供 Windows x64 与 ARM64 原生构建、当前用户安装版及便携版；安装和运行不要求管理员权限。
3. **产品能力**：包含任务管理、提醒、JSON 导入导出、托盘、全局快捷键、鼠标穿透与恢复、开机自启、置顶/置底、设置和批量操作。
4. **数据与迁移**：使用本地 JSON 文件及轮换备份；旧网页数据由用户在旧版本导出 JSON 后手动导入，不读取浏览器配置目录。
5. **选择语义**：窗口级可选中性由鼠标穿透控制（FR-74）；任务列表多选是独立能力（FR-80~96）。默认穿透恢复快捷键为 `Ctrl+Alt+L`，可在设置中更改。
6. **隐私与安装**：离线运行、无遥测；安装程序仅为当前用户安装，卸载默认保留数据，删除数据必须由用户明确选择。

## 11. 原生实现与交付边界

### 11.1 构建与运行

应用以 C++20 和 Windows SDK 实现，使用 CMake/MSVC 构建。最终运行进程是原生 Windows 可执行文件，不启动浏览器、WebView、Node.js、PowerShell、批处理启动器或本地 HTTP 服务；发布产物按 x64 与 ARM64 分开构建和校验。

### 11.2 模块职责

| 模块 | 职责 |
| --- | --- |
| `native/domain` | 任务校验、增删改、排序、筛选、选择与提醒规则 |
| `native/application` | 用例编排、应用设置、持久化调用、提醒与数据传输协调 |
| `native/persistence` | 版本化 JSON、原子写入、每日轮换备份、导入/导出与旧数据兼容 |
| `native/presentation` | 原生浮窗、任务列表、编辑、设置、布局、主题与 UI Automation |
| `native/platform/windows` | 单实例、窗口层级与穿透、托盘、全局热键、通知和当前用户自启动 |
| `installer` / `scripts` | 当前用户安装、便携打包、版本/架构/校验和验证与 GitHub 发布 |

### 11.3 本地数据与迁移

- 当前应用数据：`%LOCALAPPDATA%\DesktopTodoList\data.json`；每日备份保存在 `backups\`。
- 原生版本早期的 `state.json` 在启动时兼容迁移到 `data.json`，原文件保留用于恢复。
- 旧网页版本的 `desktopTodoList.v1` 位于浏览器 localStorage，原生程序不会自行读取；用户应先从旧版本导出 JSON，再从原生应用导入。
- 安装版卸载默认只移除程序文件并保留数据；只有卸载时明确选择“删除用户数据”才移除应用数据目录。

### 11.4 发布与验收

每个版本必须通过 x64 自动化测试和 x64/ARM64 真实构建产物的架构、版本、文件布局、安装包及 SHA-256 校验。正常情况下，x64/ARM64 应用程序与安装程序应使用有效 Authenticode 签名；若发布负责人明确批准无证书例外，可发布未签名版本，但 `checksums.txt` 必须标记 `unsigned`，发布说明必须明确告知 Windows 可能显示未知发布者或 SmartScreen 安全提示，且校验流程仍须验证所有文件哈希、架构和版本。只配置一项签名密钥时必须阻止发布。v2.0.2 是经批准的未签名例外版本。签名用于验证发布者身份，但新证书或低下载量版本的 SmartScreen 信誉可能尚未建立，不承诺立即消除所有 SmartScreen 提示。需要真实交互桌面、屏幕阅读器或特定显示设备的检查保留为有负责人的人工验收项，不用模拟结果代替。
