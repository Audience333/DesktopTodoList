# DesktopTodoList 完整需求交付与架构优化设计

## 1. 背景

DesktopTodoList 已具备任务管理、智能视图、列表多选、本地持久化和 Windows 宿主等主要能力，但当前实现仍有以下问题：

- `src/js/app.js` 同时承担渲染、交互、设置、导入导出、窗口控制和提醒，文件超过 1500 行。
- `host/launcher.ps1` 同时承担生命周期、托盘、快捷键、指令路由和窗口状态管理，修改风险较高。
- 自动备份、合并导入、提前提醒、快捷键自定义、关闭行为、大列表性能等需求尚未完整交付。
- 单元测试覆盖核心状态逻辑，但浏览器交互、提醒和真实 Windows 集成测试不足。
- 一键测试批处理存在中文 Windows 编码兼容问题。

本设计在不改变 `docs/需求文档.md` 需求范围的前提下，完成全部 P0、P1、P2 与非功能需求，并将现有实现渐进式迁移到职责清晰、可独立测试的模块。

## 2. 目标与约束

### 2.1 目标

1. 完整满足 PRD v1.2 中 FR-01 至 FR-96 以及 NFR-01 至 NFR-10。
2. 保留现有任务、设置和宿主状态，不要求用户手工迁移数据。
3. 将前端业务、浏览器界面、系统服务和 Windows 宿主解耦。
4. 为数据可靠性、提醒、导入导出、列表性能和宿主操作建立可重复验证。
5. 保持双击 `启动待办.bat` 即可运行，无安装和管理员权限要求。

### 2.2 不变约束

- 保持纯 HTML、CSS、JavaScript 与 PowerShell 5.1 技术栈。
- 不引入 npm、CDN、第三方运行时或联网服务。
- 主数据继续使用 localStorage 键 `desktopTodoList.v1`。
- 应用离线运行，不采集遥测，不上传用户数据。
- 支持 Windows 10 1809+、Windows 11、x64 和 ARM64。
- 浏览器模式继续支持核心任务功能；宿主能力缺失时明确降级并提示。

## 3. 设计原则

### 3.1 渐进迁移

不整体重写。先用测试固定现有行为，再逐个抽取职责。每次迁移只改变一个模块边界，并保留兼容适配器，直到所有调用方完成迁移。

### 3.2 单向依赖

依赖方向固定为：

`UI → 应用服务 → 核心状态/领域规则 → 持久化或宿主端口`

核心业务不得引用 DOM、Notification、fetch 或 PowerShell 宿主对象。UI 不直接读写 localStorage。

### 3.3 兼容优先

数据结构变化必须通过显式迁移函数完成。旧数据读取后在内存中升级，校验成功后才覆盖主存储；失败时保留原始数据并尝试备份。

### 3.4 失败可见

存储、注册表、快捷键、通知、窗口样式和导入失败都必须形成结构化错误，并由 UI 或托盘向用户显示。不得只写日志或静默吞掉关键失败。

## 4. 目标目录结构

### 4.1 前端

```text
src/js/
  app.js                    # 启动、依赖组装和顶层协调
  core/
    task-store.js           # 任务增删改查、筛选、排序、统计
    selection-store.js      # 单选、多选、范围选择、焦点和清理
  services/
    persistence.js          # 主数据保存、读取、校验、迁移和配额错误
    backups.js              # 每日备份、七份轮换、恢复
    import-export.js        # JSON 导出、解析、合并和覆盖
    reminders.js            # 到期判断、补提醒、提前提醒、去重
    host-bridge.js          # 宿主能力探测、指令、响应和降级
  ui/
    task-list.js            # 列表渲染、虚拟化、拖拽、框选、行内编辑
    task-editor.js          # 快速录入和任务详情
    settings.js             # 设置读取、校验、保存和能力降级
    notifications.js        # 页面提示、声音与系统通知适配
    keyboard.js             # 页面快捷键与焦点路由
```

现有 `store.js`、`storage.js` 和 `host.js` 在迁移期保留为兼容入口，向新模块转发调用。全部调用方迁移并通过回归测试后，才删除重复内部实现。

### 4.2 Windows 宿主

```text
host/
  launcher.ps1              # 参数解析、启动顺序、消息循环和清理
  server.ps1                # 静态文件与本地指令 API
  window.ps1                # Win32 声明及原子窗口操作
  settings.ps1              # 宿主设置、迁移和原子写入
  hotkeys.ps1               # 注册、冲突检测、更新和注销
  tray.ps1                  # 托盘图标、菜单、数字/状态图标和通知
  commands.ps1              # 页面指令校验与分发
```

PowerShell 模块只通过返回对象报告成功或失败，不在底层函数中直接改变页面状态。`launcher.ps1` 负责组合模块和向页面发布结果。

## 5. 数据设计与迁移

### 5.1 主数据

继续使用 `desktopTodoList.v1`。现有 `schemaVersion: 1` 数据必须保持可读。若为新增设置字段提供默认值，可继续兼容 schema 1；若任务结构发生不兼容变化，则升级 schema 并提供逐版本迁移链。

迁移顺序：

1. 读取原始字符串。
2. 解析 JSON，保留原始字符串直到迁移成功。
3. 依据版本逐步迁移。
4. 校验和清洗迁移结果。
5. 在内存中启动应用。
6. 下一次成功保存时写入新结构。

### 5.2 自动备份

备份采用索引键与分项键：

- `desktopTodoList.v1.backups.index`
- `desktopTodoList.v1.backups.YYYY-MM-DD`

每日首次成功加载后创建一次备份。创建新备份前验证当前状态可序列化；写入成功后更新索引。只保留最近七个日期，清理失败不会影响主数据写入，但必须记录可见警告。

保留现有 `desktopTodoList.v1.backup` 作为旧版应急备份来源。首次成功创建新格式备份后不再写入旧键，但恢复界面仍能读取它。

### 5.3 导入

导入分成解析和提交两个阶段：

- 解析阶段只读取、迁移、校验并给出预览，不修改当前数据。
- 用户明确选择“合并”或“覆盖”后才提交。
- 合并时以任务 `id` 为主键；同 id 使用导入版本覆盖，同时保留导入文件中的有效字段。
- 提交前为当前数据创建安全备份。
- 提交失败时恢复提交前状态并显示错误。

## 6. 功能补齐设计

### 6.1 提醒

提醒服务接收当前时间和任务列表，返回应提醒任务，不直接操作 UI。提醒记录使用 `remindedAt`；当截止时间或提醒设置发生实质变化时清空该字段，使新时间可以再次提醒。

支持 0、5、10、30 分钟提前提醒。启动补提醒按一次汇总处理，运行期间每 20 秒检查，并在窗口重新可见时补检。

通知适配顺序：

1. Windows 宿主通知。
2. Web Notification。
3. 页面提示与短提示音。

系统能力允许时，通知提供“完成任务”动作；不支持动作的通知仍应能点击后显示窗口并定位任务。

### 6.2 设置与快捷键

设置界面允许编辑全局显示快捷键和穿透恢复快捷键。输入被标准化为修饰键加单一主键，保存前由宿主试注册：

- 注册成功后替换旧快捷键并持久化。
- 注册失败时保留旧快捷键，返回冲突提示。
- 穿透恢复快捷键注册失败时禁止进入新的穿透状态，除非托盘逃生通道可用并已向用户明确提示。

关闭行为提供“退出程序”和“收起到托盘”。浮窗模式默认收起，但用户设置具有最终优先级。

### 6.3 托盘状态

托盘应显示待办数量和穿透状态。由于 Shell 托盘没有通用文本角标接口，宿主运行时生成有限尺寸的内存图标：

- 0–99 显示实际数字，超过 99 显示 `99+` 的等价紧凑标识。
- 穿透状态使用明显的斜杠或不同底色。
- 无法生成动态图标时降级为图标状态变化加 tooltip，不影响托盘菜单逃生功能。

### 6.4 批量操作与文件拖入

批量工具栏增加截止时间和标签操作。批量加标签支持添加与移除，仍执行最多五个标签的任务级约束。

页面接收拖入的单个 `.json` 文件，执行与设置页导入相同的预览和合并/覆盖流程。其他文件或多个文件给出明确提示。

### 6.5 大列表性能

任务少于或等于 200 条时继续完整渲染，保持现有交互简单可靠；超过 200 条时启用固定估算高度的窗口化列表，并为当前焦点、选区、拖拽目标和搜索命中保留必要的缓冲区。

如实际任务行高度因备注而变化，则使用测量缓存修正偏移。键盘移动和 `scrollIntoView` 由列表控制器统一处理，避免焦点元素尚未挂载。

性能测试以 1000 条任务为基准，统计业务筛选排序时间和 DOM 渲染完成时间。目标为 PRD 指定的 200 毫秒；若测试机器明显受限，报告原始数据而不放宽产品目标。

## 7. 页面状态与数据流

1. `app.js` 初始化持久化、store、宿主桥和 UI 控制器。
2. 持久化层加载、迁移和校验状态。
3. store 接收已验证状态，并向订阅者发布不可变的变更事件摘要。
4. UI 控制器只重新渲染受影响区域，避免每次操作重建全部页面。
5. 持久化订阅业务变更，以 300 毫秒防抖保存。
6. 宿主桥接收需要系统能力的命令，并异步发布成功、失败和实际状态。
7. 页面设置以宿主回传的实际状态为准，避免界面显示与窗口状态不一致。

## 8. 错误处理

统一错误对象至少包含：

- `code`：稳定错误码。
- `message`：可直接显示的中文信息。
- `source`：storage、import、reminder、host、hotkey 等来源。
- `recoverable`：用户是否可以重试。
- `detail`：仅用于日志的技术信息，不包含敏感路径之外的不必要数据。

关键失败处理：

- 主数据损坏：读取最新有效备份并提示。
- 主数据与备份都损坏：不覆盖原始键，启动空白安全状态并引导导出损坏数据。
- 配额不足：停止自动覆盖，提示立即导出。
- 宿主失联：切换浏览器降级状态并禁用相关设置。
- 快捷键冲突：保留旧绑定并显示冲突。
- 窗口命令失败：恢复 UI 开关到宿主实际状态。

## 9. 测试设计

### 9.1 JavaScript 自动测试

按模块测试：

- 任务状态、排序、筛选和统计。
- 选择模型及删除后的 id 清理。
- 数据迁移、损坏恢复、配额错误。
- 每日备份和七份轮换。
- 合并与覆盖导入的预览、提交和回滚。
- 到期、提前、补提醒和重复提醒抑制。
- 快捷键路由和设置校验。
- 虚拟列表范围计算与焦点定位。

新增行为采用红—绿—重构：先运行新增测试并确认因功能缺失失败，再写最小实现，最后运行完整测试集。

### 9.2 PowerShell 自动测试

- 静态服务器、token 和目录穿越防护。
- 设置读写与损坏设置恢复。
- 快捷键解析、注册替换和冲突回滚。
- 指令参数白名单和错误回传。
- 托盘菜单状态计算。
- 窗口位置可见性与高 DPI 换算。

会修改注册表或创建真实窗口的测试必须在 `finally` 中恢复原状态，并支持在权限不足或无交互桌面时报告“跳过”，不得因空句柄继续执行并产生误导性异常。

### 9.3 人工 Windows 验收

在 Windows 10 和 Windows 11 上分别验证：

- 双击启动、冷启动和单实例。
- 自启写入、启动及关闭清理。
- 托盘、关闭行为和待办角标。
- 全局快捷键冲突与更新。
- 置顶、置底、穿透及两条逃生通道。
- 多显示器和 125%/150%/200% DPI。
- 原生通知和点击动作。
- x64 与 ARM64 可运行性。

## 10. 交付阶段

### 阶段 A：基线与可靠性

- 修复一键测试入口编码。
- 建立统一测试命令和环境跳过规则。
- 抽取持久化、备份及导入导出模块。
- 完成自动备份、七份轮换和合并导入。

### 阶段 B：提醒与设置

- 抽取提醒服务与通知适配器。
- 完成提前提醒、声音和宿主通知。
- 完成快捷键编辑、冲突回滚和关闭行为设置。

### 阶段 C：列表与交互

- 拆分任务列表、编辑器和键盘控制器。
- 完成批量截止时间、标签和 JSON 文件拖入。
- 实现 200 条以上窗口化渲染。

### 阶段 D：宿主重构与发布验收

- 拆分宿主设置、快捷键、托盘和命令路由。
- 完成动态图标和实际状态回传。
- 补齐 README、隐私、卸载及故障排查文档。
- 执行性能、兼容性和真实 Windows 验收。

每个阶段结束时都必须能够独立运行，且不得以未完成的后续阶段作为当前阶段正常工作的前提。

## 11. 完成定义

任务只有同时满足以下条件才视为完成：

1. PRD 每一条 FR/NFR 都有实现证据或明确的环境验收记录。
2. JavaScript 与 PowerShell 自动测试全部通过；环境不支持的系统级测试以明确跳过而非失败或假通过呈现。
3. 现有 `desktopTodoList.v1` 数据可无损加载。
4. 自动备份、损坏恢复和配额失败路径经过测试。
5. 真实 Windows 验收覆盖托盘、注册表、通知、快捷键、窗口层级和穿透逃生。
6. 1000 条任务性能数据满足 PRD 目标或如实列为未达标缺陷。
7. 分发目录无第三方运行时，体积小于 5 MB。
8. 用户文档包含使用、隐私、数据导入导出、卸载和故障处理说明。
